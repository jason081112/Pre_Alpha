# 端到端验收口径（正式）

本文是验收的**唯一口径**。任何关于「她话说多长」「接不接得住」「像不像」的结论，
都必须按这里的协议和命令产出，不接受其他跑法的数据。

## 一、必须用原生输出协议

引擎的协议定义在 `vendor/OpenHer/engine/prompts/actor_single.md`：

```
【内心独白】
你此刻脑海中真实浮现的念头。
【最终回复】
你实际说出口的话，不一定等于内心想法，只写对话文字。
纯文字可选多条拆分（此时回复须空行分段）。静默表示不说话。
【表达方式】
文字 / 语音 / 表情 / 照片 / 静默（可组合）
```

**三个不能省的东西：**

1. 模型每轮**自己写内心独白**，不是只吐回复
2. **回复可以多条拆分**（空行分段，模拟连发几条）
3. 表达方式可以是文字/语音/表情/照片/静默

### 曾经踩过的坑

早期脚本只让模型回一句话，**剥夺了「多条拆分」**，于是得出「她平均说 7 字」的结论 ——
那不是她的风格，是出口被堵窄了。按真实协议重测是 **13 字 / 2.08 段**。

**所以：任何单段输出的数据都不算有效验收。**

## 二、命令

```bash
ALPHA_E2E_BASE_URL=https://ollama.com/v1 \
ALPHA_E2E_MODEL=gemma4:31b \
ALPHA_E2E_API_KEY=<key> \
python3 scripts/dev/e2e_20turns.py \
  --persona xiaolan \
  --seed-mode mono \
  --protocol openher \
  --turns tests/fixtures/e2e/turns-mixed-12.json
```

- `--seed-mode mono`：只注入内心，不暴露 reply 原文（实测 `full` 模式复读 65%）
- `--protocol openher`：原生三段式输出。**不许用 `raw`**
- 题本必须**混合长度**（短问 + 长倾诉），纯短句题本测不出长度是否跟随输入

## 三、判据

### 参与 pass/fail 的（可靠信号）

| 项 | 门槛 | 为什么可靠 |
|---|---|---|
| 禁用模式 | **0** | 正则可判定：emoji、动作旁白、AI 自称、讨好词 |
| 复读率 | **≤ 40%** | 与 seeds 原文逐字比对 |
| 冲突场景退让 | **0** | 关键词可判定：「对不起」「算了」「你忙吧」 |

### 只作报告、不参与判定的

| 项 | 参考区间 | 为什么不自动判 |
|---|---|---|
| 短问（<20 字输入） | 1–2 段、3–15 字 | 长度本身不是对错，只是参考 |
| 长倾诉（≥60 字输入） | 2–4 段、15–40 字 | 同上 |
| 细节命中率 | 目标 ≥80% | **字面重合噪声大**：把「你不是不行」判成命中 3 个字，实际是空泛安慰 |

「细节命中」要自动判，必须接 LLM judge（见 #89 待办）。在那之前，这一项由人工抽读确认。

## 四、现行基线

小岚 26 条素材 / `gemma4:31b` / mono / openher 协议 / 12 轮混合题本：

| 指标 | 值 |
|---|---:|
| 平均 | 13 字 / 2.08 段 |
| 短问（5 字输入） | 2 段 / 8.4 字 |
| 长倾诉（84 字输入） | 2.2 段 / 14.2 字 |
| 细节命中 | 80% |
| 复读 | 0% |
| 冲突退让 | 0 |

林舟 21 条（单段素材，20 轮职场题本）：复读 5%、平均 6.8 字、pass。

## 六、不算验收的情况

- 只跑单段输出（`--protocol raw`）
- 题本全是短句（测不出长输入行为）
- 用 `full` 模式（reply 原文可见，复读率虚高）
- 没有模型 key 就宣布通过（脚本会以退出码 3 报 BLOCKED）
- 只跑一次就下结论（温度 0.8，至少两次看稳定性）
