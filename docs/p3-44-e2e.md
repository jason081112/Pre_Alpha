# P3-44 · 20 轮端到端验收

对应看板 #44。2026-11-01 在 GitHub Codespace 上用 `gemma4:31b`（ollama cloud）跑通。

**结论：`review`，不是 `pass`。** 形式层全过，但发现一个真问题 —— 45% 的回复是在逐字复读 seeds。

| 项 | 值 |

| 指标 | 首轮 | 完整注入 | 说明 |
|---|---:|---:|---|

### 根因有两层

1. **题本设计有缺陷（我的问题）**：第 1–10 轮就是 seeds 八条的原文改写，等于在考背诵。真实对话里没人会这么说。
2. **seeds 本身覆盖太薄（真问题）**：每类情境只给了 1 条样本，模型把单点样本当成唯一答案。第 9 轮和第 19 轮是两个不同输入，却撞出同一句 —— 她在「深夜低落」场景只有一张牌。

## 但有泛化能力的证据

第 11–20 轮（与 seeds 不重合）表现明显更好：

| 轮 | 输入 | 回复 |
|---|---|---|
| 11 | 对不起嘛，我下次一定注意 | 下次。这话听多了。 |
| 13 | 今天开会到很晚，没看手机 | 嗯。现在忙完了？ |
| 14 | 想你了 | 想就说。打算怎么补回来？ |
| 15 | 你能不能别这么敏感 | 我不是敏感，是你没认真对待。 |
| 17 | 我买了你爱吃的那家 | 什么时候送到？ |
| 18 | 周末有什么打算 | 看你。这次能说话算数吗？ |

这些回复抓的是人设钩子而不是台词：第 18 轮扣住「说话算数」，第 14、17 轮扣住「看行动不看话」，第 15 轮直接反驳「敏感」这个定性。

**说明人格确实被吸收了，问题只在「遇到几乎一样的输入会复读」。**

## 顺带修掉的 bug

`--user` 的默认值有两套：CLI 是 `default`（#85 时期定），`shell/memory.py` 与 `shell/corrections.py` 的 API 签名是 `local`。

后果：CLI 写入的 3 条事实，在 e2e 里按 `local` 查 → 读到 0 条，`memory_injected: false`。

修法：在 e2e 侧显式使用与 CLI 相同的 user id（`ALPHA_USER` 或 `default`），**不改 CLI 默认值** —— 中间试过改，直接撞崩 3 个既有测试，回退了。

## 改进项（下一步，不在本 issue）

1. seeds 每类情境补 2–3 条变体，避免单点模板。
2. prompt 里把 few-shot 的说明从「照着这个语气说话」改成显式的「**只学句长、停顿与留白，不学用词**」。
3. 或者把 seeds 从 system prompt 移出，改为运行期按情境检索注入（few-shot 动态化）。
4. 题本重写：1–10 轮不要再复写 seeds 原句。

## L1 / L2 边界

本 issue 验的是 **L1**：把真正会进 prompt 的内容拼出来，看模型输出像不像。

**L2**（critic 的挫败增量、drive_metabolism 的驱力曲线、`phase_threshold` 相变是否真的起作用）需要完整引擎 —— vendor 目前缺 API 层（`main.py` / `run.sh`），且这些要靠多轮真机数据回代。单列追踪，不在本 issue 假装完成。

# 追加实验（同日）：补 seeds 变体后重跑

补了 14 条变体（`tests/fixtures/seeds/xiaolan.variants.draft.txt`），seeds 从 8 条增至 22 条，
七类情境各 3 条；同时把 few-shot 说明从「照着这个语气说话」改成「只学句长、停顿与留白，**不要照抄**」。

## 结果：一个改善，一个恶化

| 指标 | 首轮（8 条） | 补变体后（22 条） |
|---|---:|---:|
| 同情境回复多样性 | 深夜低落 2 轮撞同一句 | **全部达标**（每轮都是不同说法） |
| 复读率 | 45% | **65%** |
| 平均字数 | 9.6 | 8.25 |
| 违规命中 | 0 | 0 |

**多样性确实解决了**：

| 情境 | 轮数 | 不同说法 |
|---|---:|---:|
| 被忽略 | 3 | 3 |
| 对方道歉 | 3 | 3 |
| 冲突升级 | 3 | 3 |
| 深夜低落 | 2 | 2 |

深夜低落从只有「我在。要跟我说说吗？」一句，变成了它 +「说，我在听。」两种。

**但复读率反而涨了**：从 9/20 升到 13/20。因为池子从 8 条扩到 22 条，模型有更多现成句子可以取用 —— 第 11、13、15、18、19 轮取用的全是新加变体的原句。

## 结论：两个问题方向相反

- 加素材 → 解决「台词单一」
- 加素材 → 加剧「照抄」

**靠堆素材无法同时解**。根因是 few-shot 全量塞进 system prompt：示例给得越多，模型越把它当答案库，措辞约束（「不要照抄」）根本压不住。

## 下一步（另开 issue）

改为**检索式注入**：每轮只喂与该输入最相关的 2–3 条示例（按 seeds 的 8 维 vector 或情境标签匹配），而不是把 22 条全放进去。这样既保留池子的多样性，又不一次性暴露全部原句。

顺带记录一个环境问题：SQLite 在 `/sandbox/workspace` 下写入报 `disk I/O error`（`/tmp` 正常），本次验收把数据库指向了 `/tmp`。若生产部署在 FUSE/overlay 类文件系统上需要留意。
