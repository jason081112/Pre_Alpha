# Provider 训练政策与不训练承诺核对（#77）

> 结论先行：**本文件不是「所有 provider 都不会训练」的证明**，而是一份逐家核对清单。
> 每家 provider 的训练开关、保留期、关闭方式都必须有人登录控制台或查阅条款后填写；
> 未核实的项一律保持「待人工核对」，不得改写成「已关闭」。

## 为什么需要这份文件

我们在隐私政策里承诺「不把你的对话用于训练我们的模型」。这句话要成立，需要三层同时为真：

1. **平台默认模型**（`dashscope/qwen-plus-latest`）的 provider 不用 API 数据训练；
2. **用户自带 Key** 时，对应 provider 的政策也不训练（或用户已知情并自行承担）；
3. **我们自己**不把对话用于训练、不二次分享。

第 3 层由代码与审计保证（见 `#59` 仓库扫描、`#100` 处置审计）；第 1、2 层只能靠人工核对 + 留证。

## 新增 provider 上线清单

新增一家 provider 时，以下全部完成才算「可上线」：

- [ ] `shell/providers.json` 增加条目（模型、base_url、api_key_env）
- [ ] 本文档新增同名小节，三个问题都有答案，状态不是「待人工核对」
- [ ] 条款快照归档到 `docs/legal-snapshots/`，文件名含 provider 与日期
- [ ] `python3 scripts/dev/gen_models_page.py` 重新生成模型披露页
- [ ] `python3 scripts/dev/check_provider_policy.py` 通过
- [ ] 若「无法关闭训练」：不加入平台默认路由；BYOK 场景在隐私政策中单独披露

## 复核触发条件

- 任一家 provider 更新条款（订阅其政策更新邮件）
- provider 调整默认保留期或引入新的模型族
- 我们新增默认路由、或把某家 provider 从 BYOK 提升为默认
- 每 6 个月定期复核一次
