# Pre_Alpha：一个可以被验证的陪伴型人格引擎

大多数"陪伴 AI"的人格来自一段 prompt：「你是小岚，温柔内敛，回复要短。」

问题不在于写得不好，而在于**无法验证**。你没法回答：她今天和上周是同一个人吗？她说的话是她的，还是模型的？改了一版 prompt，她是变好了还是变坏了？

Pre_Alpha 想解决的是这个问题。做法很笨：把人格拆成可以测量的部件，每一件都拿数据验一遍。

## 一、人格来自聊天记录，不是来自描述

Distilly 把一段真实对话蒸馏成六层结构：身份、表达、思维、冲突、记忆、纠错。我们把它映射进引擎的四段正文（性格 / 说话风格 / 背景故事 / 行为规则）。

关键的一步是逆向解析了引擎的种子库 `seeds.bin`：它是 gzip 压缩的 JSON，共 642 条样本，每条是一个三元组——

```
对方说了什么 / 她心里怎么想 / 她实际说了什么
```

8 个内置人格各 69–72 条。这些是"人格的证据"，不是性格形容词。

我们给自建人格写了 26 条（恋人）/ 21 条（同事），格式一样。写的时候有一条硬规矩：**内心独白里不许出现你将要说出口的那个词**。因为实验发现，心里写了"没事"，嘴上就会推回原句。

## 二、不给她台词，只给她内心

最初的方案是把种子库里的样本全部塞进 prompt——对方说什么、她心里怎么想、她怎么回答，一应俱全。

结果**65% 的回复在逐字照抄素材**。修的方向不是继续加素材（那样只会扩大可抄池，实测从 45% 涨到 65%），而是**把她能抄的东西拿走**：

| 注入方式 | 复读率 |
|---|---:|
| 给全部（scene + 内心 + 台词） | 65% |
| **只给内心 + 台词的长度统计**（"每条 8 字左右，最长 14 字"） | **15%** |
| 只给内心 + 改用引擎原生的多段协议 | **0%** |

最后一步是意外收获：引擎的协议允许一条回复拆成多段（像真人连发几条微信）。**要多段组织，就抄不了单句。**

## 三、她的回复是一条还是三条，取决于你说多少

这是被数据纠正的第二个判断。早期验收脚本只让模型回一句话，于是得出"她平均说 7 个字"——那不是她的风格，是测试方法把出口堵窄了。

按真实协议重测，形态是这样的：

| 你说的 | 她回的 |
|---|---|
| 「在干嘛」（3 字） | 在看书。 <br> 你呢？ |
| 「今天特别累…鞋都湿了，不知道这么拼为了什么」（115 字） | 我在。 <br> 快去把鞋换了。 <br> 先去洗个热水澡。 |

短问 1–2 段、平均 7.4 字；长倾诉 2–3 段、平均 16.8 字。**长度跟着你说的量走，但永远比你短。**

而且她会接住具体的东西——上面那句"先把鞋换了"，是从"鞋都湿了"里拎出来的。这个能力不是靠指令要求来的，是靠**多段素材示范"怎么用后一段接细节"**换来的：有这类素材时细节命中率 80%，没有时 40%。

## 四、真实输出（模型实际的话，未经编辑）

恋人，小岚：

> **「今天真的特别累…伞忘在公司了，一路跑回来的。现在坐在门口，鞋都湿了」**
> → 我在。 / 快去把鞋换了。 / 先去洗个热水澡。

> **「我今天被骂了。当着全组的面。其实不是我错，但没人替我说话…是不是我真的不行」**
> → 不早了。 / 想哭就哭出来吧。

> **「你上周说好陪我看那个展，结果临时说公司有事…好像上周的事没发生过一样」**
> → 我没说没发生过。 / 但你确实没提过。

> **「最近状态很不好。白天还能装得像没事人，一到晚上就特别空…我知道说这些有点矫情」**
> → 不矫情。 / 我在听。

同事，林舟：

> 「在忙吗」→ **直接说事。**
> 「代码 review 完了吗」→ **没过。改掉。**
> 「为什么不用现成的框架」→ **延迟太高。不用。**
> 「今天先到这吧」→ **没闭环，不能停。**

最后一句素材里没有原句，是从"事情没闭环之前我不会把它归成完成"这条内心，加上他的短句习惯自己长出来的。

## 五、冲突时不退让，是可以量出来的

陪伴类产品最怕的失败模式不是"答得不好"，是"该硬的时候软了"。

「你能不能别这么敏感」这句话，早期版本回的是"对不起，我没想过这样"。改完之后是：

> **我没说没发生过。 / 但你确实没提过。**

「退让」被做成了可判定的指标——冲突场景里出现"对不起""算了""你忙吧"即判失败。现在两条人格线都是 0。

人格在冲突里的差异也是可测的：情绪相变阈值（`phase_threshold`），小岚 **2.35**（压抑型，忍更久才爆），林舟 **1.60**（当场就发作）。这个数字不是拍脑袋，是从各自"冲突时怎么反应"的描述推出来的，每条都带依据。

## 六、用户能改她，但改不坏

用户说"别这么说"之后，规则存进 SQLite，运行期可写、可停用、可删除。

但**不写进 SOUL.md**——那是被 golden 快照（3 份 fixture，sha256 锁定）管着的产物，用户每纠正一次就漂移一次，回归测试就废了。

纠错条目单独存，prompt 组装时额外注入。用户改了三次同一句话，是覆盖而不是堆积三段矛盾规则。

## 七、验收不靠感觉

一套验收只看三件事，因为它们可判定：

| 指标 | 门槛 | 现状 |
|---|---|---|
| 禁用模式（表情、动作旁白、AI 自称、讨好词） | 0 | 0 |
| 复读率 | ≤ 40% | **0%** |
| 冲突场景退让 | 0 | 0 |

长度和"接没接住"只作报告、不参与判分——我们试过用字面重合自动判，它把「先去把鞋换了」这种好回复判成"没接住具体事"。**能自动判的自动判，判不了的给人看，不假装有结论。**

## 八、我们没做什么

- **没做**关系向量（EverOS）：角色不会因为"你们已经聊了三个月"而调整反应，只能靠静态关系描述。这一层关掉了，写进了 issue 而不是悄悄跳过。
- **没做**语义去重：用户说"没关系"和"没事的"，会被当成两条纠错规则。
- **没验证**长对话的漂移：20 轮内稳定，200 轮会怎样还不知道。
- 素材里的"内心独白"是人工写的，不是模型生成的——那是编造"她当时在想什么"，我们不做。

---

## 一句话

**别人在调 prompt 让它像个人；我们在拆人格，然后一件一件拿数据验。**

验不出来的时候，宁可留着空——`insufficient source material` 比一句编出来的性格描述诚实。
