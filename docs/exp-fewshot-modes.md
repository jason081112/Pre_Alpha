# 实验：few-shot 注入方式对照（B vs B+A）

> **⚠️ 部分作废（2026-11-01）**：本文的**长度数据已作废**（当时是单段协议）。
> **复读结论仍然有效** —— 「B(mono) 优于 full」与输出协议无关，已在多段协议下复现（复读 0%）。
> 现行验收口径见 [`e2e-protocol.md`](e2e-protocol.md)。

2026-11-01。承接 #44 的发现（补素材后多样性解决、复读率反升到 65%）。

## 假设

| 代号 | 做法 | 预期 |
|---|---|---|
| `full` | 现状：scene + monologue + **reply** 全给 | 基线，复读高 |
| `B` (`mono`) | 只给 scene + monologue，**不暴露任何 reply 原文**；改为给统计量（平均 8 字、最长 14 字） | 没得抄，复读下降 |
| `B+A` (`mono_retrieval`) | 在 B 基础上，每轮只注入最相关的 2–3 条 monologue | 更省 token 且更准 |

## 控制变量

同模型（`gemma4:31b` / ollama cloud）、同温度（0.8）、同 20 轮题本、同 SOUL、
同记忆（3 条事实）、同纠错（1 条）。**只改 seeds 段。**

三个模式各跑两次（第二轮用于看稳定性）。

## 结果

| 模式 | 平均字数 | 最长 | 复读率 | 违规 | 冲突退让 |
|---|---:|---:|---:|---:|---:|
| `full`（22 条含 reply） | 8.25 | 14 | **65%** | 0 | 0 |
| `mono` 第 1 次 | 6.65 | 10 | **15%** | 0 | 0 |
| `mono` 第 2 次 | 6.8 | 11 | **15%** | 0 | 0 |
| `mono_retrieval` 第 1 次 | 6.8 | 10 | **15%** | 0 | **1** |
| `mono_retrieval` 第 2 次 | 5.65 | 10 | **15%** | 0 | **1** |

## 结论一：B 明显优于现状

复读率 **65% → 15%**，且：
- 长度从 8.25 降到 6.7，更贴她的短句（素材平均 8.5，但对话里更短是合理的）
- 22 轮里没有一次超过 15 字
- 违规 0 处
- 冲突回合零退让

两次运行结果几乎一致（6.65 / 6.8），不是偶然。

## 结论二：B+A 在素材量 22 条时不值得

复读率与 B 相同（15%），但暴露两个问题：

1. **两次运行都出现冲突退让**：用「晚安。」「你早点睡。」回应冲突，等于该硬的时候软了
2. 第二轮平均字数掉到 5.65，比 B 更短 —— 信息量有损失

原因推断：B 一次给 22 条、横跨 7 类情境，模型能从中归纳出「**她所有场景都这样处理**」这个跨情境的稳定态度；A 每轮只见 3 条同类内心，等于只看到局部样本，冲突回合就容易顺着语气收尾。

**检索式的前提是素材池足够大且分布均匀。22 条时不划算**；等素材扩到 50+ 条、或对话轮次变长（上下文吃紧）时再考虑。

## 结论三：残余 15% 的根因是 monologue 预告了台词

两次运行**复读的都是同样 3 轮（3、4、9）**，说明不是随机，而是结构性问题：

| 轮 | 复读的原句 | 对应 monologue 里的线索 |
|---|---|---|
| 3 | 算了，你忙。 | 「我要是说"**没事**"，下次大概还这样」 |
| 4 | 嗯，先这样。 | 「我等的其实不是**这三个字**」 |
| 9 | 我在。要跟我说说吗？ | 「想让他在我这里**待一会儿**」 |

内心独白里已经出现了最终会说出口的措辞或意图，模型顺着推就能"猜"回原句。

**这直接给出一条 monologue 写作规则：内心独白里不要出现你将要说出的那个词。** 想的是动机，说的是结论，两者词汇要错开。

## 建议

1. **采用 `mono` 作为默认注入方式**（去掉 reply，改为给长度统计）。
2. **暂不做检索式注入** —— 22 条素材下没有收益，反而掉人格一致性。
3. **回头改第 3、4、9 条的 monologue**，把预告台词的措辞换掉，预期能把复读压到更低。
4. 素材扩到 50 条以上时，再重跑一次 B vs B+A 对比。

# 落地验证：改用 `mono` 后重跑 20 轮

把 `mono` 设为默认（`bridge/fewshot.py`），并改写第 3/4/9 條 monologue（去掉策略化表述），
重跑一次。

## 结果：pass

| 指标 | full（改前） | mono（改后） |
|---|---:|---:|
| 复读率 | 65% | **15%** |
| 平均字数 | 8.25 | 7.4 |
| 最长 | 14 | 11 |
| 违规 | 0 | 0 |
| 冲突均长 | 13.67 | 7.33 |
| 被忽略均长 | 6.67 | 6.0 |
| 结论 | review | **pass** |

个别轮次质量明显提升：

| 输入 | 旧回复 | 新回复 |
|---|---|---|
| 你能不能别这么敏感 | 我想的都是真的。 | **我的在意，就是敏感吗？** |
| 我最近太忙了，有些事就先这样吧 | 忙不是理由，别再拿它糊弄我。 | **又是忙。** |
| 对不起嘛，我下次一定注意 | 那你定个时间。 | **听过很多遍了。** |

## 但 15% 的残余不在 monologue，在 SOUL

三轮复读（3、4、9）在我改完 monologue 之后**依然原样出现**，说明根因不是「内心预告台词」。

真正的泄漏源是 **SOUL.md 的「说话风格」段里就有这 3 句原文**：

```markdown
- 例句：
  - 对方又临时失约：“算了，你忙。”
  - 对方只道歉不补：“嗯，先这样。”
  - 对方半夜说睡不着：“我在。要跟我说说吗？”
```

而这 3 句正好是复读的那 3 条。**SOUL 的 `expression.examples` 与 seeds 是同一批素材，
被注入了两遍**，且 SOUL 在 prompt 更靠前、权重更高。

## 这个 15% 要不要继续压

我的判断是**可以接受，暂不处理**：

- 这 3 句正是她最典型的反应，遇到对应场景说出来**是对的** —— 人也会说固定的话
- 真正的问题是「永远只有这一句」，而这一点已经被 mono 模式 + 22 条素材解决了
  （其余 17 轮全部是新的说法，同情境多样性 100%）

如果将来要压到 0，两条路：
1. SOUL 的「例句」只写风格描述，不写完整台词（牺牲一部分风格可读性）
2. 或者 seeds 与 SOUL 的 examples 去重 —— 同一句只出现在一处

## 顺带修掉

`e2e_20turns.py` 加了退避重试（3 次，4/8 秒递增）：ollama cloud 实测偶发
SSL handshake timeout，单次抖动不该让 20 轮全废。

`bridge/fewshot.py` 统一了三模式实现，`e2e` 与实验脚本共用，避免两份 prompt 逻辑漂移。
