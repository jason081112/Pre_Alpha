# Open Core 边界

Alpha 是 **open core**：公开仓库给你完整的本地能力；托管的质量层与控制面在私有仓库。

## 开什么

| 层 | 内容 |
|---|---|
| 协议 | persona schema、refine 接口契约、事件格式 |
| 客户端 | Web / PWA、CLI |
| 自托管 | 单用户服务端、Docker Compose、BYOK |
| 引擎适配 | provider 注册表、路由 / 回退、错误分类 |
| 本地蒸馏 | 解析、分块、去重、PII 清洗、schema、基础 prompt |
| 可信度 | 加密实现、导出 / 删除工具 |

## 闭什么

| 层 | 内容 | 在哪 |
|---|---|---|
| 精修蒸馏 | prompt 链、语气校准、矛盾修复、评分 rubric | 私有 `alpha-cloud` |
| 评测资产 | 黄金集、人工偏好、调参记录 | 私有 |
| 控制面 | 账号、认证、订阅、配额、多租户 | 私有 |
| 托管记忆 | 同步、备份、压缩 / 迁移、embedding 调参 | 私有 |
| 审核风控 | 分类器、关键词、封禁策略 | 私有 |
| 商业 | 定价、漏斗、渠道 | 私有 |
| 角色资产 | 人设、音色、立绘、主题 | CC BY-NC |

## 架构

```
客户端（公开）
  │ 原始聊天记录只留在本地
  ▼
distill-core（公开）
  │ persona.json（结构化，不含原文）
  ▼
refine API（私有）
  │ 只收 persona JSON，拒收 raw_text
  ▼
陪伴引擎 + 托管记忆
```

硬规则：

1. `refine` 请求体出现 `raw_text` / `messages` / `chat_log` / `transcript` 一律 422。
2. 服务端默认不持久化 persona 原文；云同步需用户显式开启。
3. 自托管不依赖 refine，基础质量可用；云端是“更好”，不是“能用”的前提。
4. 对外只说“原文不上传”，不说“数据不上传”。

## 为什么不开全部

- 代码不是护城河，**个人数据引力 + 长期记忆 + 蒸馏质量**才是。
- 质量层必须跑在服务端才能闭得住；放进客户端等于公开。
- 全开源会方便竞品直接做托管，AGPL 只保护自托管入口，不保护质量层。
